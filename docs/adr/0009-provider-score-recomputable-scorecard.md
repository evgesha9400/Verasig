# ProviderScore is a pure, recomputable, in-memory scorecard — honestly partial until simulation, fully evidence-traced

`ProviderScore` + `ProviderScoreExplanation` are produced by a new pure `services/scoring/` (`hygiene.py` per-component metric math → `scorecard.py` weighted assembly) over durable inputs, and are **recomputed on read, never persisted** — the second in-memory recompute after the lifecycle fold ([ADR 0007](0007-lifecycle-fold-pure-recomputable.md)), not a stored projection ([ADR 0006](0006-extraction-outcomes-shape-and-lifecycle.md)) and not durable evidence ([ADR 0008](0008-deletion-evidence-durable-projection.md)). The composite is a plain weighted-normalized sum `score = Σ(normalized × weight)` over **only** the components currently backed by evidence; the simulation components (`sim_expectancy`, `drawdown`, Slice 9) and any empty-denominator component are **excluded with a note**, never fabricated, so the Stage-8 score is honestly partial (`simulated_count = 0`). Every measured component carries typed-prefix `evidence_refs` naming every row used to **measure** it (numerator and denominator), so 100% of the score reconstructs from stored evidence.

We did this because the score adds **no new information** over its durable inputs and observes nothing ephemeral (unlike `DeletedSignalEvidence`, whose live snapshot vanishes — [ADR 0008](0008-deletion-evidence-durable-projection.md)). Its sources are all durable: append-only raw ([ADR 0001](0001-two-layer-raw-capture.md)), the recomputable extraction projection ([ADR 0006](0006-extraction-outcomes-shape-and-lifecycle.md)), and the durable deletion evidence ([ADR 0008](0008-deletion-evidence-durable-projection.md)). A stored score could therefore only drift from a recompute — precisely the line [ADR 0007](0007-lifecycle-fold-pure-recomputable.md) drew for the fold — so `computed_at` + `weights_version` stamps reproduce a past score by re-running at that version over the immutable inputs, and re-weighting is "a config change; the score recomputes deterministically" (spec §8).

## Considered options

- **Persist as a recomputable projection** (key `channel_id` [+ `weights_version`], symmetric with [ADR 0006](0006-extraction-outcomes-shape-and-lifecycle.md) `record_outcome`) **or an append-only score history**: rejected — the score is a pure function of durable inputs and retains nothing ephemeral, so the row can only go stale; this is the exact reason [ADR 0007](0007-lifecycle-fold-pure-recomputable.md) kept the fold in memory. v0 weights are an explicit throwaway placeholder, so a stored re-weighting history is YAGNI for Stage 0.
- **Renormalize present weights (`÷ Σweight`) to force `score ∈ [0,1]`**: rejected — contradicts the frozen §7 (`score = sum(contribution)`, `contribution = normalized × weight`) and test-plan row 8 (`composite = Σ(normalized × weight)`). The honest signal is a **partial** score plus `simulated_count = 0` and a note, not a renormalized 1.0 for an unsimulated provider.
- **Score the pending-sim / empty-denominator components at 0 or 0.5**: rejected — fabricates a `normalized` value with empty `evidence_refs` and penalizes a provider for Verasig's own build state. Excluding + noting keeps the invariant "every listed component has `evidence_refs`" literally true (symmetric with the pending-sim handling).
- **Score the context components** (`signal_frequency`, `active_user_proxy`): rejected — spec §8 marks them "context", not a quality direction. More signals ≠ better (spam posts constantly) and a bigger audience ≠ better signals (and the proxy must **never** be a quality claim), so they ride at **weight 0** — informational, still evidence-traced.
- **Emit `evidence_availability` unconditionally** from `captured / (captured + suspected)`: rejected — a never-rescanned channel stores 0 gap rows and would read 1.0, indistinguishable from a rescanned-clean channel. It is emitted **only when a rescan provably ran** (≥1 deletion-evidence row with `method ∈ {SNAPSHOT_DIFF, ID_GAP}`; `LIVE_EVENT` deliberately excluded, since a Slice-10 live-delete proves a real-time observation, not a full historical gap measurement), else excluded + noted.
- **Bare-UUID `evidence_refs`**: rejected — `RawTelegramMessage` (composite PK) and `TelegramChannel` (int) have no UUID. A typed-prefix grammar (`channel:` · `message:<ch>/<msg>` · `event:` · `signal:` · `unrecognized:` · `deletion:` · `parser_drift:` · `filter_drift:`) references every row kind and resolves back to stored rows; bulk message-corpus denominators anchor on `channel:<id>` (a deterministic `count_messages` query) rather than enumerating thousands of `message:` refs.
- **One `scoring.py` / metrics in `domain/score.py`**: rejected — splits responsibility poorly. `hygiene.py` returns **un-weighted** measurements (raw / normalized / evidence_refs / notes) and `scorecard.py` applies `ScoreWeights` → final `ScoreComponent`, so re-weighting touches only assembly and `domain/` stays IO-free contracts.

## Consequences

- **New contracts** (`domain/score.py`, matching frozen [data-contracts §7](../work/stage-0-local-observer/data-contracts.md) 1:1): `ScoreComponent`, `ProviderScore`, `ProviderScoreExplanation`, plus `ScoreWeights(version, by_component)` + `DEFAULT_WEIGHTS = ScoreWeights("v0", …)`. `computed_at` defaults `_now()` and is injected for deterministic tests (mirrors `detect_deletions(detected_at)`, [ADR 0008](0008-deletion-evidence-durable-projection.md)).
- **Fourth placement on the storage taxonomy.** Append-only raw ([ADR 0001](0001-two-layer-raw-capture.md)) · recomputable projection persisted ([ADR 0006](0006-extraction-outcomes-shape-and-lifecycle.md)) · in-memory recompute ([ADR 0007](0007-lifecycle-fold-pure-recomputable.md)) · durable non-recomputable evidence ([ADR 0008](0008-deletion-evidence-durable-projection.md)). `ProviderScore` joins the fold as the **second in-memory recompute** — no migration, no table, no `conftest` change.
- **v0 weights (placeholder, never claimed optimal):** scored quality — `sim_expectancy` 0.30 + `drawdown` 0.20 (**pending Slice 9**), `deletion_behaviour` 0.20, `completeness` 0.10, `parser_confidence` 0.10, `evidence_availability` 0.10 (Σ = 1.0); context — `signal_frequency`, `active_user_proxy` at 0.0. Until Slice 9 the active quality weights sum to 0.50, so the Stage-8 ceiling is 0.50 and `notes` records the pending sim. Slice 9 activates the two sim components with **zero weight-config change**.
- **Per-component math:** `deletion_behaviour` = 1 − (CONFIRMED∧`was_signal_candidate` deletions ÷ `RawSignalEvent` count); `completeness` = mean over signals of present-among-{entry, stop, ≥1 TP} ÷ 3 (MARKET counts as entry-specified); `parser_confidence` = DETERMINISTIC ÷ total candidates; `evidence_availability` = `count_messages` ÷ (`count_messages` + `ID_GAP` gaps); `signal_frequency` = candidates ÷ observation-window-days; `active_user_proxy` raw = `subscriber_count` (or 0), normalized = mean of saturated {subs, median views, median forwards} over available inputs.
- **Pure + offline:** `hygiene.py` and `scorecard.py` take domain lists + `ScoreWeights` + `computed_at`, return contracts; the decisive tests use crafted in-memory objects with **zero** Telegram/LLM/market/network. The offline `verasig score <ref>` reads via repos then calls the pure builder (mirrors `_fold_channel`) and exits 1 on an unknown channel.
- **Boundary:** no `SimOutcome` (Slice 9) — the sim components are noted-pending; no persistence; no Streamlit scorecard (a later concern). `CONTEXT.md` is corrected: `ProviderScoreExplanation` is **not stored** (recomputed), and the `Active-user proxy` blend is subscriber count + median post views + forwards (**reactions are not captured at Stage 0**).
