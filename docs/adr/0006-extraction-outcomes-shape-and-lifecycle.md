# Extraction outcomes: a provenance-free TradeIntent + a recomputable per-event projection

Extraction is split into two concerns that were previously conflated in `ExtractedSignal`. (1) **Shape** — the trade parsed from text (`symbol`, `side`, entry/stop/targets, leverage, provider-stated confidence) becomes `TradeIntent`, a provenance-free contract. (2) **Recording** — `ExtractedSignal(TradeIntent)` adds the event linkage (`event_id`, `channel_id`), the lifecycle role (`event_type`), and the extraction provenance (`extraction_method`, `rule_id`). Both extractors are now symmetric, pure `text -> TradeIntent | None` functions (`deterministic_parser.parse(rule, candidate_text)` and `LlmExtractor.extract(candidate_text)`); the `ExtractService` is the single place that attaches linkage (one `_link` helper for both paths). The derived outcome tables (`extracted_signal`, `unrecognized_signal`, `parser_drift_warning`) become **recomputable per-event projections**: a re-extract upserts the winning outcome keyed on `event_id` and clears the losing sibling + stale drift through one `record_outcome` repo write.

We did this because the frozen contracts collided: `LlmExtractor.extract(candidate_text)` ([data-contracts §9](../work/stage-0-local-observer/data-contracts.md)) cannot satisfy `ExtractedSignal`'s required `event_id`/`channel_id` ([§3](../work/stage-0-local-observer/data-contracts.md)) from text alone, and the deterministic parser had taken the event purely to self-stamp linkage — an asymmetry between two extractors with the same role. Splitting shape from linkage dissolves the collision at the root (each extractor produces only what text can honestly yield), centralises provenance, and makes the linkage rules change in one place. It also exposed that a per-method-constant `parser_confidence` carried no information beyond `extraction_method`, so it was dropped.

## Considered options

- **Service stamps onto a placeholder-linkage `ExtractedSignal`** (adapter builds a signal with fake `event_id`, service overwrites via `model_copy`): rejected — constructs a deliberately-invalid object to immediately patch it, and `model_copy(update=…)` bypasses validation.
- **Change the Protocol to `extract(event: RawSignalEvent)`** (symmetric with the old `parse(rule, event)`): rejected — couples a pure text→structure transform to the event/persistence model, edits §9's frozen input signature, and still leaves linkage logic duplicated across both extractors.
- **Keep `parser_confidence` as a per-method constant** (1.0 deterministic / 0.7 fallback): rejected — a float restating `extraction_method`, which is already stored; fabricates accuracy. Slice 8 derives the parse-reliability component from the `extraction_method` distribution + the unrecognized rate instead.
- **Per-table upsert with no cross-table cleanup**: rejected — the one-of outcome spans two tables, so a normal distillation-loop transition (`unrecognized → extracted` once rules improve) leaves a stale sibling row and Slice 8 double-counts.
- **Merge the two outcome tables into one `extraction_outcome` table**: viable (one-of becomes a DB `UNIQUE(event_id)` constraint) but rejected for Stage 0 — sparse nullable columns, `symbol`/`side` lose their `NOT NULL`, and a row↔(ExtractedSignal|UnrecognizedSignal) impedance. The two-clean-tables + `record_outcome` design keeps the columns honest and localises the invariant.

## Consequences

- **Amends [ADR 0001](0001-two-layer-raw-capture.md).** Append-only is now scoped explicitly to **raw capture** (`raw_telegram_message`, `raw_signal_event`). **Derived** extraction-outcome tables are recomputable projections: `record_outcome` upserts on `event_id` (`ON CONFLICT DO UPDATE`), deletes the losing sibling, and upserts-or-clears the `parser_drift_warning` — so re-extraction after rule improvements transitions an event's outcome cleanly with no stale rows.
- **New contract:** `TradeIntent`; `ExtractedSignal` now extends it. `parser_confidence` removed from `ExtractedSignal`.
- **Symmetric extractor seam:** `parse(rule, candidate_text) -> TradeIntent | None` and `LlmExtractor.extract(candidate_text) -> TradeIntent | None`; `ExtractService._link(intent, event, method, rule_id)` is the single linkage site. `evaluation.py` simplifies (drops its dummy-event construction).
- **Idempotency:** `UNIQUE(event_id)` on `extracted_signal`, `unrecognized_signal`, `parser_drift_warning`; re-running `extract` is `+0` rows and incremental over new events.
- **`extraction_method` is load-bearing** as the parse-reliability signal — it must always be stamped by the service (never defaulted from the wire).
